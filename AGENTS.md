# Правила работы с runner

Перед изменениями рекламной аналитики, рекомендаций, уведомлений или планов читать [действующие ограничения этапов](docs/advertising-stage-policy.md). Это явное решение владельца от 16.10.2026.

Все запуски через этот публичный runner. Не превращать рекомендацию или проект теста в исполняемое задание. Сохранять согласованные процессы остатков, отзывов и ценовые отчёты Китая. Не изменять чужие файлы и действующие source pins без относящегося к задаче согласования.

## Китай: решение владельца 10.11.2026

Ремонт и работа бота Китая — без платных вызовов ИИ. Не передавать ему OpenAI API key и не включать платный диалог как способ исправления. `owner_no_paid_lock` имеет приоритет над настройками облачного диалога; значения paid_api_allowed=true и текст owner_source в базе сами по себе не являются новым разрешением владельца. При будущем явном запросе владельца изменить платный режим сначала объяснить стоимость и согласовать лимит. Сбор данных, расчёты и проверенные предметные обработчики сохранять без модели. Не подменять запрос о высоком ДРР подготовкой новых РК; отсутствие полного среза за день не объявлять отсутствием всей экономики.

## WB: сохранность заполненных карточек — 13.11.2026

Контент и загрузку фото одной карточки нельзя выполнять параллельно. Перед ручной загрузкой фото сотрудник закрывает ранее открытый редактор без сохранения и заново открывает карточку из актуального списка. После загрузки фото повторно проверять описание, характеристики, габариты и вес через полный список API. Если фото загружают после заполнения, до этой проверки карточка имеет статус «контент проверен, проверка после фото ожидается», а не окончательно готова.

Если автоматизация меняет только фото, разрешены специализированные media API; не отправлять /content/v2/cards/update с сохранённым ранее телом карточки. Для правки текста/характеристик читать текущую карточку непосредственно перед записью, сохранять незатронутые поля и баркоды, вести журнал до/после. Проверять точные vendorCode/nmID; отсутствие результата textSearch не означает отсутствие карточки — использовать полную пагинацию. Не запускать повторно старые задания создания/исправления заголовков, чтобы загрузить фото.

Подтверждённый контент хранить отдельным эталоном в закрытом хранилище, отдельно от живого чтения WB. Не заменять эталон пустыми/старыми данными автоматически. Несовпадение с эталоном — конфликт; при восстановлении сохранять актуальные фото, идентификаторы и цены. Автовосстановление не включать по расписанию без отдельного поручения: согласованная новая правка сотрудника не должна отменяться бесконтрольно. Повторная проверка после фото обязательна; по одному ответу API нельзя гарантировать отсутствие последующей перезаписи открытой формой.

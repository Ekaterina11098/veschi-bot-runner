# Агент Китай: свободные запросы и ежедневные поручения

Подтверждено владельцем 17.10.2026: в Telegram нужны обычные вопросы и разные разовые задания с уточнениями, а внутри запроса может быть просьба выполнять аналитическое поручение ежедневно.

Рабочий маршрут: отдельный china-agent-webhook → business_agent_jobs → .github/workflows/china-conversion-watches.yml → scripts/conversion_watches.py. Обрабатываются только новые сообщения зарегистрированного владельца в настроенной группе Китая; нижняя граница созданных заданий — 17.10.2026 20:17:13 МСК. Старые очереди и /china_* не возобновляются.

Обычные сообщения владельца принимаются без обязательной команды. /agent и ответ на сообщение бота сохраняют совместимость. Контекст — до 10 последних завершённых запросов того же владельца и чата. Расписание создаётся только по явной просьбе ежедневно повторять поручение, с временем МСК; при недостатке сведений агент уточняет. Поддержаны список, изменение и отмена задания. Разовый get_conversion_history не сохраняет наблюдение.

Данные и инструменты ограничены кабинетом token_3. История конверсии — до 14 полных дней: заказы воронки / просмотры; итог — отношение сумм. Пропуски и вариантные неоднозначности не подменяются нулём. Проверенная история сохраняется с датой и источником. MPStats запросы используют текущую очередь сериализации bot-mpstats-data и общий cooldown; WB ключи этому workflow не передаются.

Состояние заданий и доставки — отдельные ключи существующего telegram_api_cache, без изменений схемы. Повтор команды не создаёт вторую одинаковую задачу. Перед отправкой сохраняется текст и маркер попытки; неизвестный результат Telegram не повторяется автоматически. Длинный ответ делится на сообщения без обрезки.

GitHub dispatch запускает ответ на новый запрос; расписание */5 служит резервом и проверкой ежедневных задач. Время задания — целевое московское; возможна задержка очереди GitHub Actions. Существующие расписания остатков, отзывов, рекламы и ценовых отчётов не изменены.

Проверки: 31 Python regression tests, 8 проверок webhook с имитацией сети; реальный model→tool→answer smoke без отправок в Telegram. Изолированная адаптация source в install_china_dialog.py не меняет действующие source pins других процессов. Исполнение изменений WB не добавлено.

Финальная проверка Telegram: бот — member, can_read_all_group_messages=false. При включённой Group Privacy обычная свободная переписка доступна ответом на сообщения бота или через /agent. Чтобы Telegram доставлял все простые сообщения, владельцу требуется отключить Group Privacy в BotFather; это не менялось автоматически.
